# 安卓动态海面调查

调查日期：2026-10-25。对应已交付的安卓测试版 0.1.0；本次为调查记录，尚未修改功能或重新打包。

APK SHA-256：`f691af94d488ef4c5a86026b270b0bae8d8f6acab94e1d381a70ce5d09e4aea2`。

## 已确认的现象

使用同一个 APK，在 Android 15、WebView 124.0.6367.219 的 x86_64 模拟器中复现：

| 条件 | 实际播放 | 应用开关 |
| --- | --- | --- |
| 默认设置，无减少动效信号 | 缓慢缩放与平移 | 开启 |
| 海浪大小为 0 | 完全静止，动画端点相同 | 仍显示开启 |
| WebView 收到减少动效信号 | 动画被取消 | 仍显示开启 |
| 减少动效期间，把应用开关关闭再打开 | 仍然静止 | 显示开启 |

正常条件下，计算得到的变换矩阵和截取的背景像素都发生变化，因此没有在这一测试环境中复现“动画有效但完全没有渲染变化”。

实际修改安卓的 `animator_duration_scale` 为 0 后，当前 WebView 没有立即更新减少动效信号；结束应用进程并重新启动后，信号变为 true，海面停播。恢复原系统设置后，信号也没有立即清除；再次重启进程后恢复播放。这个结果仅证明当前测试环境的表现，不代表所有安卓或 WebView 版本都相同。

## 代码与计算

`web/mobile.js` 的 `applyAppearance` 在下列任一条件下将 `data-still` 设为 true：

1. 应用内动态海面设置关闭。
2. `prefers-reduced-motion: reduce` 匹配。
3. 页面处于 `document.hidden` 状态。

开关的 `aria-pressed` 却只读取应用内的 `settings.motion`，没有展示实际停播状态或原因。CSS 还会在减少动效时直接取消所有动画，因此反复切换应用开关不能绕过该条件。

当前海面是一张静态 PNG 的整体缩放与平移，没有实现水波形变。默认海浪大小为 56：单向周期为 `24 - 56 × 0.15 = 15.6` 秒，完整往返 31.2 秒，纵向平移参数为 `56 × 0.08 = 4.48` CSS 像素，缩放从 1.04 到 1.0596。默认数值有效，但视觉变化很弱。

## 结论与边界

已确认的问题是开关未反映实际播放状态，以及本测试环境中系统动效变化未及时同步。用户提到手机可能开启“减少动态效果”，与该触发路径一致，但没有连接用户手机读取实际状态，不能认定其设备的唯一原因。

模拟器冷启动曾发生一次输入超时，日志同期显示较高 I/O 等待；没有证据将它归因于海面动画。后台样本的页面可见状态未发生预期变化，因此没有据此验证真机的页面隐藏与恢复行为。

## 后续修复方向

1. 展示实际播放状态及停播原因，而不是仅显示用户的开关偏好。
2. 在原生安卓层监听系统动画设置，在返回前台时重新读取并同步界面。
3. 明确海浪大小为 0 的静止含义，调整当前图片动效的强度和名称；如要真实水波，需要另行选择实现并评估耗电。

复现脚本为 `tools/motion_probe.mjs`。原始 JSON、截图与模拟器日志输出在 `outputs/motion-investigation`，属于本机诊断产物，不纳入源码提交。[浏览器减少动态效果说明](https://web.dev/articles/prefers-reduced-motion)。
